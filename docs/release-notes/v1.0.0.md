# v1.0.0 — Scenario-based FSI hosted agents on Microsoft Foundry

> **Disclaimer.** Everything this solution produces is AI-generated from public SEC filings and
> web sources for demonstration only. It is not investment advice, has not been reviewed or
> approved by any qualified person, and must not be relied on for any investment, credit,
> underwriting or regulatory decision.

First tagged release of this repository as a **replicate-ready solution template**. One command
(`deploy.ps1`) stands up an isolated environment in your subscription with three scenario-based
hosted agents, each reaching governed Anthropic `financial-analysis` skills through its own
Foundry toolbox, behind a FastAPI BFF and a Next.js portal on Azure Container Apps.

| Scenario | Hosted agent | Toolbox | Deliverable |
|---|---|---|---|
| Equity Research & Valuation | `fsi-equity` | `tb-equity-research` | `.xlsx` |
| IB Pitch / Deal Prep | `fsi-ib-pitch` | `tb-ib-pitch` | `.pptx` |
| PE LBO Screening | `fsi-pe-lbo` | `tb-pe-lbo` | `.xlsx` |

## Highlights

- **Bring your own model.** The model is an explicit deployment input (name, version, SKU,
  capacity) that flows into the single Foundry model deployment, all three hosted agents and the
  API. Suggested: `gpt-6-astra` `2026-09-03` GlobalStandard. `gpt-6-sol` and `gpt-6-luna`
  (`2026-09-22`) are alternatives. The portal and `/api/health` show the environment and model
  deployment in use.
- **Clearer outcomes.** Every run ends `complete`, `partial` or `error`. When the model cannot
  finish the full artifact, the BFF still delivers a one-sheet summary, and the portal labels it
  a *Partial result* rather than reporting success.
- **Durable, private artifacts.** Artifact ids are stateless and encode the private blob
  reference, so downloads survive scale-to-zero, new revisions and multi-replica routing. Blob
  access is Entra ID only. A storage outage returns a retryable `503`.
- **Provenance-first SEC data.** The new `get_financial_fact_pack` SEC EDGAR MCP tool returns
  normalized annual 10-K facts with accession, period and unit provenance. Every scenario agent
  is told to discover and call it first for public-company figures, keeping missing or
  conflicting values unresolved instead of inventing them.
- **Optional WebIQ news enrichment.** A user can paste a WebIQ key, which is held in browser tab
  memory only, and enter an explicit news query. Results reach the agent as untrusted, cited
  context. A key on its own never triggers a search, and "Clear key and run without WebIQ"
  retries without it. The key is sent only as the `X-WebIQ-Key` header over HTTPS and is redacted
  from telemetry and validation errors.
- **Honest agent output.** The instructions carry an updated disclaimer, and agents are told
  never to claim a QC pass, sign-off or approval.
- **Storage-policy resilience.** `-DemoStoragePolicyOptOut` applies a policy's documented
  `SecurityControl=Ignore` exclusion to the storage account only, and only where the policy owner
  approves it. It never enables anonymous blobs or shared keys.
- **Sturdier deployment.**
  - `deploy.ps1` detects the `microsoft.foundry` azd extension and maps tenant and resource group
    into the azd env.
  - It checks every native command exit code.
  - It hash-syncs the hosted runtime into `agent-src` before deploying.
  - It deploys the agents one at a time, with retries.
  - It finishes by running `scripts/validate.py --portal-origin`, which checks CORS from the
    portal as well as downloading real OOXML from each scenario.
- **Tests and CI.** GitHub Actions runs these on every PR:
  - API unit/integration tests (run flow, WebIQ)
  - SEC EDGAR fact-pack tests
  - validator tests
  - portal unit and mocked-API Playwright browser tests
  - portal typecheck and build
  - Bicep build
  - a check that the runtime mirror is in sync

## Breaking changes: model parameters and PowerShell 7 are required

There is no built-in model default any more:

- `infra/main.bicep` requires `modelName`, `modelVersion` and `modelCapacity`. `modelSku`
  defaults to `GlobalStandard` and `agentModelDeploymentName` defaults to `modelName`.
- `deploy.ps1` requires `-ModelName`, `-ModelVersion` and `-ModelCapacity` unless you pass
  `-SkipInfra`. `-ModelDeploymentName` and `-ModelSku` are optional.
- The deploy scripts now declare `#Requires -Version 7.0`, so run them with PowerShell 7+
  (`pwsh`). Windows PowerShell 5.1 turns redirected native-command stderr into terminating
  errors.

```powershell
az cognitiveservices model list -l eastus2 `
  --query "[?model.name=='gpt-6-astra'].{version:model.version, skus:join(',', model.skus[].name)}" -o table
az cognitiveservices usage list -l eastus2 `
  --query "[?contains(name.value,'gpt-6-astra')].{name:name.value, used:currentValue, limit:limit}" -o table

.\deploy.ps1 -EnvName <env> -Location eastus2 `
  -ModelName gpt-6-astra -ModelVersion 2026-09-03 -ModelSku GlobalStandard -ModelCapacity <k-TPM> `
  -SecEdgarUserAgent "Your Name your.email@example.com"
```

GlobalStandard quota is **subscription-global per model**, so capacity held by any other
deployment of the same model in the subscription counts against the same limit. Pick a
`-ModelCapacity` that fits the free quota.

## Upgrading from pre-release `master`

- Pre-release `master` hardcoded `gpt-5.4` (`2026-03-05`). To keep an existing environment on
  that model, redeploy with
  `-ModelName gpt-5.4 -ModelVersion 2026-03-05 -ModelCapacity <current>`. To move to
  `gpt-6-astra`, pass its values. If `-ModelDeploymentName` is omitted, the deployment name comes
  from the model name, and the agents and API pick it up from `AZURE_AI_MODEL_DEPLOYMENT_NAME`.
- Key Vault names are now `kv-<first 12 chars of env>-<token>`. Environments whose names are 12
  characters or fewer keep their existing vault. Longer names previously exceeded the Key Vault
  limit and failed to deploy.
- `/api/health` adds `environment_name` and `model_deployment_name`. The `done` SSE event adds
  `outcome`, and artifacts carry `kind` (`generated` or `summary`). Clients that ignore unknown
  fields are unaffected.
- `scripts/provision_foundry.ps1` now updates existing skills in place (`azd ai skill update`)
  rather than deleting and recreating them.
- Re-run `deploy.ps1` so the synced runtime, toolboxes and API/portal images match this release.

## Known limitations

- **Heavy prompts can time out.** A single prompt that combines deep SEC retrieval with a full
  multi-sheet model can hit a model-layer 408 at about 360 s. The BFF retries once, asks for a
  corrective artifact turn, then falls back to a one-sheet summary reported as a *Partial
  result*. This is expected behavior, not a regression.
- **Storage policy.** A subscription Azure Policy can flip storage `publicNetworkAccess` back to
  `Disabled` after deployment, which breaks artifact downloads with an error that looks like
  missing RBAC. `deploy.ps1` re-asserts the setting, and `docs/runbook.md` documents the repair,
  the exemption and the opt-out.
- **azd credential lookups can flake** under back-to-back deploys. `deploy.ps1` deploys the
  agents one at a time with retries.
- **SEC EDGAR MCP is AGPL-3.0.** It runs as its own container from
  [`stefanoamorelli/sec-edgar-mcp`](https://github.com/stefanoamorelli/sec-edgar-mcp), and
  `agents/mcp/sec-edgar/` keeps that attribution. Review the license before redistributing a
  modified image.
- **Framework instrumentation is disabled** in the hosted runtime to avoid a known span-attribute
  serialization bug.
- **Model-authored wording is not verified.** The instructions forbid claiming approval or an
  independent review, but the model still chooses file names and labels. For example, one PE LBO
  validation run named its workbook `..._Audited.xlsx`. Treat every artifact as an unreviewed
  draft.
- Output quality depends on the chosen model, the public data available, and the pinned upstream
  skill revision (`-SkillsRef`).
